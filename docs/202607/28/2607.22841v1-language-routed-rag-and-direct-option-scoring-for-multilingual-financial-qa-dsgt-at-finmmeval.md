## 摘要
我们提交了DS@GT对FinMMEval 2026任务1的解决方案，该任务是一个多语言金融考试问答基准，涵盖英语、西班牙语、希腊语、中文和印地语。CFA、EFPA和CPA等金融认证考试需要结构化领域的推理，这是标准NLP基准无法捕捉的，而在检索和表示基础设施不发达的语言中，这一挑战更加复杂。我们在LangGraph上构建了一个检索增强流水线，该流水线检测查询语言，并使用BGE-M3嵌入和FAISS索引从包含30,209条多语言知识库中检索语义相关的示例。然后，系统通过检索增强直接评分（RADS）对答案进行评分，读取候选选项字母上的下一个标记的log概率，而不是生成自由形式的输出。对于低资源语言，我们使用加权互惠排名融合融合了每种语言和跨语言的检索索引。模型选择是语言路由的：阿拉伯语、中文和印地语使用Qwen3-14B；英语使用Qwen2.5-14B；希腊语使用Llama-3.1-8B，这种路由来自经验消融实验，揭示了显著的语言不对称性能差距。值得注意的是，思维链提示显著降低了希腊语的准确率（从90.7%降至20.9%），而启用Qwen3的默认思考模式使阿拉伯语的RADS性能下降到接近随机水平。我们的结果表明，有效的多语言金融推理需要语言感知的检索、模型路由和审慎的评分策略选择。

## Abstract
We present DS@GT's submission to FinMMEval 2026 Task 1, a multilingual financial exam question answering benchmark spanning English, Spanish, Greek, Chinese, and Hindi. Financial certification exams such as the CFA, EFPA, and CPA demand structured domain reasoning that standard NLP benchmarks do not capture, and this challenge compounds across languages where retrieval and representation infrastructure is underdeveloped. We build a retrieval-augmented pipeline on LangGraph that detects query language and retrieves semantically relevant exemplars from a 30,209-entry multilingual knowledge base using BGE-M3 embeddings and FAISS indexing. The system then scores answers via Retrieval-Augmented Direct Scoring (RADS), reading next-token log-probabilities over candidate option letters rather than generating free-form output. For low-resource languages, we fuse per-language and cross-lingual retrieval indices using weighted Reciprocal Rank Fusion. Model selection is language-routed: Qwen3-14B for Arabic, Chinese, and Hindi; Qwen2.5-14B for English; and Llama-3.1-8B for Greek, a routing derived from empirical ablations that reveal substantial language-asymmetric performance gaps. Notably, chain-of-thought prompting significantly degrades Greek accuracy (90.7% to 20.9%), and enabling Qwen3's default thinking mode collapses Arabic RADS performance to near-chance levels. Our results indicate that effective multilingual financial reasoning requires language-aware retrieval, model routing, and deliberate scoring strategy selection.

## 2. 论文提出的方法论

### 核心思想
构建一个 **语言路由的检索增强生成（RAG）管道**，并结合 **检索增强直接评分（RADS）** 来替代传统的自由文本生成，实现确定性的答案选择。

### 关键技术细节
- **语言检测与查询路由**：通过测试集 ID 前缀或 Unicode 脚本检测语言，根据语言选择不同的检索策略。
- **多语言知识库构建**：聚合 30,209 条经过处理的金融问答示例，覆盖英语、中文、希腊语、西班牙语、阿拉伯语、印地语。每个条目包含问题、选项、标准答案和语言标签。
- **语言感知索引分区**：按语言创建独立的 FAISS 索引分片（IndexFlatIP，1024 维 BGE-M3 嵌入），同时保留全局跨语言索引。对低资源语言（如希腊语，仅 171 条）采用加权互惠排名融合（RRF）：
  \[
  \text{RRFscore}(d) = \sum_{i \in \{\text{global},\ell\}} \frac{w_i}{k + r_i(d)}
  \]
  其中 \(w_{\ell}=2.0\)（原生语言权重），\(w_{\text{global}}=1.0\)，\(k=60\)。
- **自适应多范围检索**：当原生索引规模 ≥20 条时，仅使用原生索引；小于 20 条时使用 RRF（原生+全局）；无原生索引时只使用全局索引。保留 top-5 示例。
- **检索增强直接评分（RADS）**：构建包含系统提示、5 个检索示例和待回答问题的提示，计算模型对每个有效选项字母（A/B/C/D）的 log-probability，取最大值作为预测答案：
  \[
  \hat{a} = \arg\max_{\ell \in \mathcal{L}_q} f_\theta(\text{prompt})[t_\ell]
  \]
- **语言路由模型选择**：根据语言选择 LLM：阿拉伯语/中文/印地语→Qwen3-14B，英语→Qwen2.5-14B，希腊语→Llama-3.1-8B。**必须禁用 Qwen3 的思考模式**（`enable_thinking=False`），否则 RADS 失效。

### 算法流程（文字说明）
1. 输入问题 → 语言检测 → 根据索引规模选择检索策略（专用/加权RRF/全局）
2. BGE-M3 编码问题，在对应 FAISS 索引中检索最相似的 5 个示例
3. 构建提示（系统+5个示例+问题+选项）
4. 将提示送入语言路由选择的 LLM，只进行一次前向传播
5. 读取选项字母的 log-probability，取最大值作为答案

## 6. 论文的主要结论与发现

1. **模型路由不可替代**：单一 LLM 无法在所有语言上最优。Qwen3-14B 在中文上比 Qwen2.5-14B 提升 4.2pp，但在英语上倒退 22.9pp；Llama-3.1-8B 在希腊语上比 Qwen3-14B 高 19.5pp。
2. **RADS 优于生成式方法**：RADS 在除阿拉伯语（Qwen2.5 下）外的所有语言上匹配或超越少样本生成，且解析失败率为 0%（中文 8,869 题全部成功）。
3. **翻译后进行求解是严格降级**：NLLB-200 翻译策略在所有语言上均落后其他方法（-14 至 -20pp）。
4. **思维链 + 自一致性具有语言非对称性**：希腊语从 90.7% 崩溃至 20.9%（-69.8pp），印地语降 19pp，英语降 34.3pp，仅在中文上略有提升（∼66% vs RADS 的 66.6%）。
5. **Qwen3 思考模式必须禁用**：启用后阿拉伯语 RADS 准确率从 71.7% 跌至接近随机。
6. **基础模型能力是主要瓶颈**：印地语上，知识库扩展仅带来 +1pp 提升，而与 Claude Opus 4.7 的差距高达 17pp，表明检索质量已足够，但模型本身在多语言金融文本上的能力不足。

## 7. 优点

- **系统设计的语言感知性**：从检索路由（按语言分区/加权RRF）到模型选择（按语言切换LLM）再到评分策略（RADS），每个环节都考虑了语言的特殊性，避免“一刀切”。
- **RADS 的实践优势**：消除了解析失败风险，支持确定性输出，且通过禁用思考模式解决了 Qwen3 的兼容问题，设计简洁有效。
- **消融实验深入且反直觉**：揭示了模型能力的非传递性（Qwen3 英语倒退）、CoT 的灾难性退化、翻译路线的低效，这些发现对实际系统设计有直接指导意义。
