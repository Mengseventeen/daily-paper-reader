## 摘要
分析10-K文件、表格披露和宏观经济报告等金融文档需要专家推理和大量时间。然而，现有的检索增强生成系统往往难以处理混合文本-表格结构或金融文档的海量规模。为应对这些挑战，我们提出了分层重排序器（Hierarchical Reranker），这是一种专为提升大规模金融数据集检索性能与生成可靠性而设计的RAG框架。该系统整合了三项关键创新：检索前优化（Pre-Retrieval Optimization），通过归一化、关键词扩展和表格转换提升查询清晰度和搜索效率；分层重排序架构（Hierarchical Reranker Architecture），通过两阶段排序机制提升检索精度；以及长上下文管理（Long-Context Management），在扩展上下文下通过自适应输入划分与融合保持推理准确性。在包括FinQA、FinanceBench和ConvFinQA在内的多个基准测试中，该系统取得了0.7918的NDCG@20分数，并展现出更优的事实一致性。其鲁棒性还通过在ACM-ICAIF '24金融RAG挑战赛中获得第二名得到了进一步验证。本工作提出了一条可部署的、面向领域优化的RAG流水线，提升了金融推理的准确性和可扩展性，为自动化审计报告和量化投资分析铺平了道路。源代码将在论文被接收后于GitHub上公开。

## Abstract
Analyzing financial documents such as 10-K filings, tabular disclosures, and macroeconomic reports demands expert reasoning and extensive time. However, existing Retrieval-Augmented Generation systems often struggle to process hybrid text-table structures or the massive scale of financial documents. To address these challenges, we propose Hierarchical Reranker, a RAG framework designed to improve retrieval performance and generative reliability across large-scale financial datasets. The system integrates three key innovations: Pre-Retrieval Optimization, enhancing query clarity and search efficiency through normalization, keyword expansion, and table transformation; Hierarchical Reranker Architecture, improving retrieval precision through a two-stage ranking mechanism; and Long-Context Management, preserving reasoning accuracy through adaptive input partitioning and fusion under extensive contexts. Across multiple benchmarks, including FinQA, FinanceBench, and ConvFinQA, the proposed system achieved an NDCG@20 score of 0.7918 and demonstrated superior factual consistency. Its robustness was further validated by achieving second place in the ACM-ICAIF '24 FinanceRAG Challenge. This work presents a deployable, domain-optimized RAG pipeline that enhances both the accuracy and scalability of financial reasoning, paving the way for automated audit reporting and quantitative investment analysis. The source code will be made publicly available on GitHub upon acceptance.

## 2. 方法论：核心思想、关键技术细节、算法流程

论文提出三段式流水线（Pre-Retrieval → Retrieval → Generation），核心设计如下：

### (1) Pre-Retrieval（检索前优化）
六步预处理，增强查询清晰度与语料库一致性：

- **Normalization（归一化）**：统一大小写、修正拼写、展开金融缩写（如EPS→Earnings per Share、YoY→Year-over-Year）、标准化计量单位（K/M），并依据文档元数据补全缺失上下文。查询和语料库都执行同样处理。
- **Keyword Extraction（关键词提取）**：提取金融领域关键词追加到查询中，增强混合文本-表格语义的捕捉能力。
- **Paraphrasing（释义）**：生成多个语义等价但语言形式不同的查询变体（如"What is Apple's revenue in 2023?" vs. "Report Apple's 2023 revenue"），扩大搜索空间。
- **HyDE（假设性文档生成）**：为每个查询生成一个合成伪文档，作为语义锚点，增强抽象查询与领域语料库之间的嵌入对齐。
- **Table-to-json（表格转换）**：使用规则脚本将Markdown表格确定性转换为JSON结构，显式保持数值与表头之间的关联。特意不用LLM转换以防止幻觉。
- **Summary（摘要压缩）**：当语料库超过10k token时，仅保留核心财务指标和关键结果，提高效率和检索精度。

### (2) Retrieval（分层重排序架构）
两阶段级联排序，实现**小-大模型协作**：

- **Stage 1 — 轻量过滤**：使用 jina-reranker-v3 快速筛选，将候选池从全量缩减至Top 100，支持最高131k token上下文，主要处理词法与浅层语义相似性；
- **Stage 2 — 细粒度语义重排**：使用 Qwen3-Reranker-8B 对Top 100重排，输出最终Top 20，捕捉跨句金融依赖关系和表格-文本数值一致性。

这种分工解耦了"广度"与"深度"：小模型处理全量粗筛，大模型集中算力于高价值候选集，兼顾检索精度与推理成本。

### (3) Generation（长上下文管理）
- **阈值设定**：通过消融实验观察到超过64k token后LLM性能显著下降，故设定64k为上下文阈值；
- **分割与融合**：当输入超过64k时，将Top-20语料分为两个语义连贯的子集，分别生成中间答案R1和R2，然后通过**条件融合**合并：仅一个含明确答案则直接采用；两个都含答案则选择置信度更高者；两者均无明确答案则输出显式"unknown"。这种设计防止跨分区产生幻觉式综合。

### 算法流程（Algorithm 1）
```
输入：查询Q，语料库C
Q' ← 归一化(Q) ∪ 关键词提取(Q)
C' ← 归一化(C) ∪ 表转JSON(C)
C100 ← 重排序器1(Q', C')
C20  ← 重排序器2(Q', C100)
```

## 8. 不足与局限
