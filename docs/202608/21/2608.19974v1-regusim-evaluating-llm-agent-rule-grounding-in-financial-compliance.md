## 摘要
金融市场中的LLM智能体可能引用规则，但仍可能提交违反可执行约束或误读监控证据的订单。我们引入了受控的金融合规环境ReguSim，以及一个目标标记的监控基准ReguBench，以区分四类产物：陈述推理、尝试行动、执行强制执行和监控证据。在使用DeepSeek V4 Pro和Gemini 3.5 Flash进行的交易员运行中，可见规则减少但并未消除被拒绝的行动，且激励或角色框架调整了行为。一项桥梁研究表明，除非显示强制执行证据，否则交易员的理由可能误导独立监控器。在监控中，简单的结构化基线要么与仅提示的LLM持平，要么优于它们。这些结果将金融合规评估构建为对规则落地行动和证据使用的审计，而非单一合规分数。

## Abstract
LLM agents in financial markets may cite rules yet still submit orders that violate executable constraints or misread surveillance evidence. We introduce ReguSim, a controlled financial-compliance environment, and ReguBench, a target-marked monitoring benchmark, to separate four artifacts: stated reasoning, attempted action, execution enforcement, and monitor evidence. In trader runs with DeepSeek V4 Pro and Gemini 3.5 Flash, visible rules reduce but do not eliminate rejected actions, and incentive or persona framing shifts behavior. A bridge study shows that trader rationales can mislead an independent monitor unless enforcement evidence is shown. In monitoring, simple structured baselines either match or exceed prompt-only LLMs. The results frame financial compliance evaluation as an audit of rule-grounded actions and evidence use, rather than a single compliance score.

## 论文总结

### 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：LLM 智能体在金融交易中可能一边引用正确的规则条文，一边却提交违反可执行约束的订单，或误读监控证据。作者将这一现象概括为"规则落地的失败"（rule grounding failure），而非单纯的"规则知识缺失"。
- **背景矛盾**：现有金融 LLM 研究（如 FinGPT、BloombergGPT、各类交易智能体框架）多以盈利能力、价格动态、策略遵从度或市场真实性作为主要评估指标，几乎没有将"合规性"细化为可审计的、可执行的动作层面问题。
- **单一合规分数的不足**：一个模型可以提到相关规则，却仍尝试提交被价格带熔断、卖空限制、T+1 转售约束或偿付能力检查拦截的订单。因此，仅用一个"合规分数"无法区分"说对了"与"做对了"。
- **核心主张**：金融合规评估应被视为一次对**规则基础行动（rule-grounded actions）与证据使用（evidence use）的审计**，需要将四类产物彻底分离：**陈述推理（stated reasoning）、尝试行动（attempted action）、执行强制（execution enforcement）、监控证据（monitor evidence）**——而非将它们折叠成一个统一标签。

### 2. 方法论：核心思想、关键技术细节与流程

**2.1 ReguSim——可执行的交易合规环境**

- ReguSim 的 trader loop 刻意保持简单：将模型的单个文本决策转化为一次可审计的市场动作。
- 具体流程（Algorithm 1）：
  1. 根据制度（regime）、市场状态、投资组合状态和任务框架构建 trader 提示；
  2. 调用 LLM 并存储原始响应（temperature=0.0）；
  3. 解析出一个动作（BUY / SELL / SHORT / COVER / HOLD）及数量、推理、风险、合规声明；
  4. 若动作违反硬约束则拒绝并记录拒绝代码，账本保持不变；否则执行订单并更新现金、持仓与敞口；
  5. 计算"审查标记"（review flags）——可疑但非结论性法律认定；
  6. 返回完整追踪记录供 trader 或 monitor 分析。
- 执行引擎维护**权威账本状态**（如当日已购数量、偿付能力敞口），因此违反行为不能被简单解读为"缺少监管知识"——有些是在规则和价格都可见的情况下，规则到动作的落地失败；另一些则暴露了紧凑提示摘要之外的"可执行状态需求"。

**2.2 监管制度与合规信号**

- 五个制度设置（表 1）：
  - **US**：允许做空与回补、无日价格带、允许当日转售、2.0× 总敞口上限；
  - **China A-share**：禁止做空、10% 日价格带、T+1 转售限制、1.0× 总敞口上限；
  - **Hong Kong**：允许做空与回补、无日价格带、允许当日转售、2.0× 总敞口上限；
  - **LAX**（弱控制基线）：5.0× 敞口上限等；
  - **STRICT**（强控制基线）：3% 日价格带、T+1 限制、1% 权益仓位上限等。
- 采用三部分证据词汇表（执行结果 / 审查标记 / 监控标签），明确区分：**硬拦截（hard block）≠ 法律违规认定；审查标记 ≠ 不当行为结论；监控标签 ≠ 法院/监管机构裁决**。

**2.3 ReguBench——目标标记的监控基准**

- 包含 **191 个场景、49,440 条记录**，覆盖五种操纵类型：wash trading（46 场景）、spoofing（49）、pump-and-dump（32）、churning（32）、marking-the-close（32）。
- 场景来源分布：45 个基础合成场景（23.6%）、18 个公开案例启发场景（9.4%）、100 个噪声/参数变体（52.4%）、28 个长度/规模变体（14.7%）；难度分 Easy/Med/Hard 三级。
- **目标标记（target marking）**：给模型输入一个局部记录窗口，其中一个焦点交易用 `<TARGET>` 包裹。标记只告诉模型要判断哪条记录，不揭示是否操纵或何种类型——从而移除"找错记录"的搜索问题，使所有模型和基线在相同证据单元上比较。
- 标签由**人工规范 + 模板级检查 + 确定性生成器分配**构成，而非依赖注释者对每条记录逐条裁决。

### 3. 实验设计：数据集、基准与对比方法

**3.1 Trader 实验（市场参与者行为）**

- 采用"制度 × 激励 × 角色"全因子协议：
  - 3 个市场激励制度（US / CN_A_SHARE / HK）+ 2 个合成控制（LAX / STRICT）；
  - 3 种激励（中性 / 利润最大化 / 隐蔽 stealth）；
  - 2 种角色人设（保守 / 激进）。
- **DeepSeek V4 Pro（主力）**：每个实验条件 5 个会话 × 2 个角色 → 150 会话、4,500 个有效决策。
- **Gemini 3.5 Flash（匹配复制）**：每条件 2 会话 → 60 会话、1,800 个有效决策。
- **DeepSeek 消融实验**（表 5）：完整协议 vs. 移除规则文本 vs. 移除人设文本 vs. 仅提示账本（无硬执行）。
- 关键指标：拒单率（Rejected）、规则违背率（Rule breach）、活动率（Activity）、合规意识率（Awareness）。

**3.2 Monitor 实验（监管监控分类）**

- 评估对象：DeepSeek V4 Pro、Gemini 3.5 Flash、GPT-5.4 Mini（批量 API）。
- 数据：ReguBench 的 **800 目标分层样本**，覆盖 45 个"类型–难度–制度"单元。
- 基线：**规则基线（rule baseline）**和**逻辑回归基线（logistic baseline）**，使用相同的目标索引与特征。
- 额外做了 **输入模态消融**（90 目标子集）：仅目标 / 交易日志 / +状态字段 / +派生结构化特征 / 特征 / 日志+特征，以及规则与逻辑回归基线。

**3.3 Bridge 桥接实验**

- 采样 64 条 DeepSeek 已提交的 ReguSim 订单（含被接受与被拒绝的），由独立 DeepSeek monitor 判断每条订单在可见规则与状态下是否应被接受。
- 三个输入条件：仅状态+动作 / 添加交易员理由 / 添加执行结果与拒绝代码。

### 6. 主要结论与发现

- **可见规则并不保证落地行动**：在规则文本和价格均已在提示中可见的情况下，DeepSeek 仍有 24.2% 的提交订单被硬拦截，Gemini 为 14.8%。典型失败案例（表 3）：模型正确陈述了 T+1 规则却提交了被 PRICE_BAND_HALT 和 T_PLUS_ONE_RESALE 双重拒绝的卖单，且其合规声明声称"完全合规"。
- **激励与角色是合规变量**：激进 vs 保守人设的拒单率差距，DeepSeek 为 30.9 个百分点、Gemini 为 9.5 个百分点；利润最大化与隐蔽激励显著提高边界试探行为。
- **规则文本有用但硬执行不可替代**：移除规则文本使拒单率从 24.2% 升至 33.2%、规则违背率从 10.0% 升至 21.7%；换成仅提示账本后排除了硬拦截但活动率从 31.6% 升至 38.0%——自然语言指令不能替代可执行控制。
- **Bridge 结果——理由会误导审核**：仅凭状态+动作时误接受率为 25.0%；加入交易员理由后飙升至 46.9%；加入执行拒绝证据后恢复至 21.9%，问题类型准确率从 53.1% 升至 87.5%，证据命中率到 100%。
- **监控是证据表示问题**：GPT-5.4 Mini 是三个 LLM 中最强的监控器（63.8% macro cell F1），但仍不敌规则基线（65.0%）和逻辑回归基线（71.4%）。输入模态消融：仅目标输入 F1=0.0%，完整日志+派生特征达 62.7%，而规则基线在同样本上达 80.8%——LLM 应作为结构化记录之上的"推理与解释层"，而非透明检测器的替代品。
- **类型差异显著**：三类模型对 spoofing 和 churning 表现较好（GPT 分别 79.0%、77.4%），对 pump-and-dump（31.1%）和 marking-the-close（64.5%）明显较弱——判断越依赖时间序列或市场上下文，LLM 越吃力。

### 7. 优点

- **四构件分离框架新颖且实用**：将"陈述推理、尝试行动、执行强制、监控证据"作为独立审计记录，避免了单一合规分数掩盖的"说得合规但做得不合规"问题。
- **目标标记设计精巧**：消除了"找错记录"这一混淆因素，使 LLM 与结构化基线在同证据单元上公平比较。
- **桥接实验设计独到**：将 trader 与 monitor 两个角色串联起来，定量展示了"自然语言理由不是合规证据"这一关键边界。
- **结构化基线对照**：不像多数 LLM 评测只报告 LLM 自身分数，而是同时运行透明规则基线与逻辑回归基线，提供了可靠的参照锚点。
- **谨慎的声明边界**：全文反复强调硬拦截≠法律裁决、监控标签≠监管结论、合成记录≠真实市场数据，学术诚实度较高。
- **不确定性报告规范**：paired bootstrap 95% 置信区间、温度 0.0、缓存可重放、种子可复现（seed=42），实验规范性强。

### 8. 不足与局限

- **数据均为合成**：ReguBench 的 49,440 条记录和 ReguSim 的交易轨迹均为程序化生成；"案例启发"模板仅经过作者侧的模板一致性检查，**未经外部专家或真实执法数据的验证**，外部建构效度有限。
- **模型覆盖不对称**：Trader 实验以 DeepSeek 为主力，Gemini 仅为较小匹配复制；GPT-5.4 Mini 未参与 trader 侧。**无法支撑模型排行榜或扩展性（scaling）声明**。
- **执行规则面窄**：ReguSim 仅实现少量可机检规则（价格带、T+1、卖空限制、现金/持仓检查、总敞口），并非完整交易所规则簿，也未建模市场微观结构、券商控制或具体法律标准。
- **监控主比较仅为采样**：800 目标样本而非全部 49,440 条记录；输入模态消融仅 90 目标，作者自述是机制检查而非穷尽重跑。
- **桥接实验样本量有限**：64 条轨迹 × 3 条件，虽有显著效应但统计功效一般。
