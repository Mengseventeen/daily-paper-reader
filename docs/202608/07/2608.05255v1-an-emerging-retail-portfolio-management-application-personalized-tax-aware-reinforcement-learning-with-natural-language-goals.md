## 摘要
零售投资者无法获得机构客户习以为常的个性化、税收感知的投资组合管理——现有的机器人顾问使用静态、基于规则的资产配置，而机构级系统所需的最低账户余额和技术栈对个人投资者而言不可及。我们呈现了一个完全构建、经过集成测试的应用，以弥合这一差距：一个FastAPI后端和网页仪表板，让用户用自然语言描述投资目标（例如，“我想要稳定增长，但下个月需要卖出一些股票来支付首付”），该目标被路由到六个投资任务之一，并由一个三阶段强化学习系统生成实时的、与券商集成的投资组合推荐——一个自监督的跨资产编码器，一个具有学习意图路由器的专家混合（MoE）配置策略，以及一个轻量级LoRA适配器，根据个人已揭示的券商行为个性化推荐，而无需重新训练共享模型。该系统功能完整，并已针对实时券商API（Alpaca，模拟交易模式）进行端到端集成测试，包括多用户认证、信任优先的预览后应用确认流程、每日电子邮件摘要，以及可审计的操作完整性链，但尚未向真实终端用户开放；我们诚实地将其报告为一个新兴的、部署前应用，具有明确的全面部署路径，同时附有14天滚动前向回测（包含自举置信区间）作为初步的部署前验证，而非生产性能。我们还报告了几条实用的工程经验——静默无效的集成路径、挂起的第三方API调用，以及端到端经验验证相对于信任检查点元数据的价值——我们认为这些经验可推广到其他基于外部实时数据源构建的应用型强化学习系统。

## Abstract
Retail investors lack access to the kind of personalized, tax-aware portfolio management that institutional clients take for granted -- existing robo-advisors use static, rule-based allocation, and institutional-grade systems require account minimums and technology stacks unavailable to individual investors. We present a fully built, integration-tested application that closes this gap: a FastAPI backend and web dashboard that let a user describe an investment goal in plain language (e.g. "I want steady growth but need to sell some shares next month for a down payment"), routes that goal to one of six investment mandates, and produces a live, broker-integrated portfolio recommendation from athree-phase reinforcement learning system -- a self-supervised cross-asset encoder, a Mixture-of-Experts (MoE) allocation policy with a learned intent router, and a lightweight LoRA adapter that personalizes recommendations from an individual's revealed brokerage behavior without retraining the shared model. The system is functionally complete and integration-tested end-to-end against a live brokerage API (Alpaca, paper-trading mode), including multi-user authentication, a trust first preview-before-apply confirmation flow, daily email digests, and an auditable action-integrity chain, but has not yet been opened to real end-users; we report this honestly as an emerging, pre-deployment application with a concrete path to full deployment, alongside 14-day walk-forward backtests (bootstrapped confidence intervals included) as preliminary, pre-deployment validation rather than production performance. We also report several practical engineering lessons -- silently-inactive integration paths, hanging third-party API calls, and the value of end-to-end empirical verification over trusting checkpoint metadata -- that we believe generalize to other applied RL systems built on external, live data sources.

## 方法论

论文提出的系统是一个三阶段强化学习管线（底层模型详见 Pishehvar 2026）：

**Phase 1：自监督跨资产表征学习**
- 自监督编码器从 OHLCV 历史数据和 50 维元数据向量（行业、市值区间、动量/波动率统计）学习每只股票的表征，使系统"ticker-identity-free"——推理时无需重新训练即可泛化到任意公开交易资产。
- 可选并行分支融合冻结的时间序列基础模型（Chronos-T5）和新闻/事件交叉注意力机制。
- **关键发现——表征坍缩（representation collapse）**：若没有显式的跨股票对比损失，所有股票收敛到近乎相同的嵌入（平均余弦相似度 0.96），分配头输出均匀 1/N 权重；加入对比目标后相似度降至 0.24，恢复差异化分配。
- 预训练损失函数：\( L_{P1} = 0.3L_{ret} + 1.0L_{mask} + 0.5L_{reg} + 0.5L_{contrast} \)，其中对比项为批次内不同股票嵌入间余弦相似度的平均。

**Phase 2：MoE（Mixture-of-Experts）组合策略**
- 四个 PPO 训练的专家头（动量、成长、防御、税收感知）由学习到的意图路由器（intent router）混合，以服务六个投资任务（短期 alpha、长期增长、资本保全、收入/税收损失收割等），同时避免梯度干扰。
- 专家训练采用分阶段课程（每个阶段只训练一个专家，其余冻结），随后进行**专家嫁接（expert grafting）**：在联合训练的路由器下重新插入每个专家最佳检查点——因为联合训练会抹除专家特化行为（动量专家 14 天 alpha 从 +3.37% 降至 +0.01%）。
- PPO 奖励函数：\( R_o = S_o - \lambda_c H_{eq} - \lambda_t \tilde{\tau} - \gamma_d \max(0, c_r - 0.05) - \gamma_s \mathbf{1}[\tau=0, t>10] + \delta_r \rho \)，其中包含目标特定基础分数、股权集中度（Herfindahl）、净换手率、现金比率惩罚、零换手惩罚和再投资比例奖励。

**Phase 3：LoRA 个性化适配**
- 一个 76 参数的 LoRA 适配器（\(\hat{\ell} = \ell_{base} + p_u AB\)，其中 \(p_u \in \mathbb{R}^{16}\) 是从券商交易历史提取的行为画像，\(r=4\)，B 初始化为零以保证部署时恒等），根据个人揭示的券商行为（交易频率、实际持有期、税档）调整策略输出，无需重新训练共享模型。每位用户的个性化产物约 1 KB。

**应用层设计**
- **自然语言目标解析**：双层解析——规则层（关键词匹配 + 正则提取年月）处理常见情况，LLM 层将其余输入解析为结构化意图对象（目标、期限、收益目标、回撤容忍度、风险水平），映射到六个任务之一。
- **税收批次感知推荐**：数据层存储真实 FIFO 税收批次（获取日期、成本基础、每批数量），使系统能在推荐时计算持有期和税后影响（如抑制距长期资本利得转化还差 26 天的 SELL）。
- **信任与安全控制**：
  - 预览后应用（preview-before-apply）确认流程，所有推荐须经用户确认才执行；
  - 硬性交易前护栏（单笔最大 $5,000、单票最大仓位、日亏损熔断、再部署比例上限），由配置强制、与模型质量无关；
  - 独立 LLM 代理风险审查：可抑制（suppress）或标记（flag）交易但绝不能引入策略未提出的动作；覆写规则为硬性数值阈值（如 10 天波动 ≥10% 强制抑制），且部署代码不信任 LLM 应用阈值——用工具返回的真实数值确定性重算区间并覆写模型判断；
  - 可审计操作完整性链：每条推荐和交易记录在追加型 SHA-256 哈希链中，并由独立公共时间戳机构（freetsa.org）作 RFC 3161 时间戳，防篡改、逐用户独立。

## 主要结论与发现

1. **系统层面的核心结论**：一个功能完整、集成测试通过的零售投资管理应用是可行的——涵盖自然语言目标解析、MoE 策略路由、LoRA 个性化、税收批次感知推荐、多层信任与安全控制、防篡改审计链，全部通过实时券商 API（Alpaca 纸面交易）端到端验证。
2. **模型层面的关键发现**：对比损失是防止跨资产表征坍缩的必要条件；MoE 联合训练会导致专家特化消失，专家嫁接（从课程检查点恢复最佳专家）是有效解决方案；LoRA 适配器（76 参数）足以实现个性化而无需重训共享模型。
3. **验证层面的结论**：回测显示对等权篮子有真实但统计上温和的正 alpha；边缘集中在短期限（30 天内）。这属于部署前验证，非生产性能证据。
4. **工程经验**：自动检测覆盖一个特性不意味着覆盖结构相似的另一特性（新闻分支静默未激活两个发布周期）；端到端经验验证（py-spy 运行时追踪）发现了代码审查无法发现的集成缺口；第三方 API 可能挂起而非失败（signal.alarm 硬超时应为默认）；缓存键需匹配上游 API 的实际返回模式（按 ticker 而非按查询缓存，将刷新调用从数万次降至 10 次）。

## 优点

1. **诚实的报告立场**：明确区分"已构建并集成测试"与"已部署"——系统尚未服务真实用户，所有数据定性为部署前验证而非生产性能。在 AI 金融应用论文中这种克制尤为难得。

5. **可复现性投入**：开源完整系统（代码仓库）、提供 bootstrap 复现脚本、固定依赖版本、记录训练硬件和超参数，并诚实说明哪些部分不可逐位复现（LLM 审查代理）及原因。

3. **对 SPY 的负 alpha 未充分解决**：作者将其归因于 SPY 成分更宽泛防御性的结构性因素，但未提供缓解验证或说明在更大股票池上是否能改善。
4. **统计功效不足**：13 个日收益对夏普比率等指标无意义（作者自己也承认并附注说明），bootstrap 方法虽有帮助但无法弥补窗口过短的根源问题。
5. **新闻/事件分支的增量价值未被证明**：News+Chronos 与 Chronos-only 统计上不可区分，作者如实报告但未做进一步分析（如新闻质量、事件密度对结果的影响）。
