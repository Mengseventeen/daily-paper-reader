## 摘要
金融文档解析要求准确性、结构一致性和可验证性，而当前的基准往往未能反映这些要求。我们提出了FinixDoc，一个面向真实世界金融文档的端到端智能体解析系统，其核心解析器是FinixDoc-VL，一个基于Qwen3-VL-4B构建的4B规模视觉语言模型。为了表征基准与部署性能之间的差距，我们引入了一个文档解析能力矩阵，该矩阵沿两个实际维度组织：视觉质量和文档规模。在这一矩阵的指导下，FinixDoc-VL通过一种领域自适应方案进行训练，该方案结合了同形字感知对比学习和带有复合领域特定奖励的多阶段强化学习。为了更好地利用我们在低质量金融文档数据方面积累的优势，并支持大规模、高质量的数据生产，我们进一步构建了一个带有置信度感知专家审核的人机协同数据工厂流水线。为了评估，我们构建了FinixDocBench，一个金融领域评估套件，涵盖数字原生、相机拍摄、超大页面和内部工作流场景，并随本技术报告发布一个经过合规审查的子集。在其主要子集上，FinixDoc-VL在评估的基线中取得了最高总分（81.43），比次优的开源模型高出5.13分，其中在内部金融工作流上的提升最大（FinixInner：84.08对比78.73）。

## Abstract
Financial document parsing requires accuracy, structural consistency, and verifiability that current benchmarks often fail to reflect. We present FinixDoc, an end-to-end agentic parsing system for real-world financial documents, with FinixDoc-VL, a 4B-scale vision-language model built on Qwen3-VL-4B, as its core parser. To characterize the gap between benchmark and deployment performance, we introduce a Document Parsing Capability Matrix organized along two practical axes: visual quality and document scale. Guided by this matrix, FinixDoc-VL is trained with a domain-adapted recipe combining homoglyph-aware contrastive learning and multi-stage reinforcement learning with composite domain-specific rewards. To better leverage our accumulated advantage in low-quality financial-document data and support large-scale, high-quality data production, we further build a human-in-the-loop Data Factory pipeline with confidence-aware expert review. For evaluation, we construct FinixDocBench, a financial-domain evaluation suite covering digital-native, camera-captured, ultra-large-page, and internal-workflow scenarios, with a compliance-reviewed subset released alongside this technical report. On its main subsets, FinixDoc-VL achieves the highest overall score (81.43) among evaluated baselines, outperforming the next-best open-source model by 5.13 points, with the largest gains on internal financial workflows (FinixInner: 84.08 vs. 78.73).

## 1. 核心问题与整体含义

- **研究背景**：金融科技企业在日常运营中需要处理海量异构金融文档（保险单、医疗票据、理赔材料、身份证件、报销单、财务报表等），文档解析直接支撑下游业务流程，对准确性、结构一致性、可验证性要求极高。
- **核心问题**：现有公开基准（如OmniDocBench）出现“性能饱和”现象——许多模型在标准基准上得分很高，但在真实金融部署中仍存在严重不足（鲁棒性弱、结构不一致、长文档/大图像处理失败）。因此，**基准性能与部署实效之间存在系统性鸿沟**。
- **关键洞见**：通过大量真实部署失败案例分析，作者发现这些不足沿两个正交维度系统变化：**输入文档的视觉质量**和**页面/文档的规模**。由此提出**文档解析能力矩阵（Document Parsing Capability Matrix）**，将场景划分为：
  - **基准收敛区（Benchmark-Converged Zone）**：主流基准多集中于此，模型间差距小；
  - **低质量区（Low-Quality Zone）**：手机拍摄导致的模糊、阴影、眩光、折痕、透视畸变、部分遮挡等；
  - **未充分探索的大规模区（Underexplored Large-Scale Zone）**：超高分辨率页面、超长保险条款、密集大表；
  - **模糊不可恢复区（Ambiguous-Unrecoverable Zone）**：图像质量极差时模型依赖语言先验产生无事实依据的推测输出，在金融场景不可接受。

## 2. 方法论

### 2.1 核心思想
论文提出**FinixDoc**——面向金融文档的端到端智能体解析系统，核心为**FinixDoc-VL**（基于Qwen3-VL-4B，4B参数规模）。选择4B规模的原因：通用VLM在低质量区的鲁棒性优于专用文档模型，且4B规模在延迟、内存和成本上满足实际部署约束。系统采用动态智能体模式，根据文档属性（模态、页面规模、质量指标）条件式调用工具，而非静态流水线。

### 2.2 系统架构关键组件
- **文档预处理工具层**：格式适配与渲染、图像归一化（方向校正）、超大页面处理（拆分-合并策略：动态路由 → 结构感知分割 → 方向感知重建）；
- **FinixDoc-VL**：标准VLM推理流水线（视觉编码→多模态融合→自回归解码），输出JSON或Markdown，严格页面对齐。

### 2.3 两阶段训练方案

**阶段一：金融视觉表示适应（同形字感知对比学习）**

- 构建**金融同形字词汇表**：分析约10万份真实金融文档，提取4500+高频字符，设计字形相似度评分模块，综合渲染字形视觉相似度（SSIM + 感知哈希）与笔画序列相似度（编辑距离 + DTW + LCS），阈值0.6过滤后每字保留5–30个高置信同形字；
- 构建三重样本（文档图像、正确文本、同形字替换的困难负样本），共约200万三元组；
- 提出**双路径对比目标**：视觉表示空间（ViT池化特征）和多模态生成表示空间（VLM融合后池化特征），使用基于边际的三元组损失，与SFT损失联合优化：
  \[
  \mathcal{L}_{total} = \lambda_1\mathcal{L}_{triplet,img} + \lambda_2\mathcal{L}_{triplet,gen} + \lambda_3\mathcal{L}_{SFT}
  \]

**阶段二：领域特定奖励的多阶段强化学习**

- 采用GRPO算法，200k训练样本（100k域外：DocLayNet、Infinity-Doc-55K；100k域内金融数据）；
- 设计**复合领域奖励**，综合文本保真度（编辑距离/AED + 表格TEDS）、检测质量（类别正确性 + IoU）、阅读顺序一致性（编辑距离），通过任务相关掩码适应JSON和Markdown两种输出；
- **多阶段优化策略**：先分别优化文本质量、目标检测、阅读顺序三个子目标，再在约10k高质量样本上用统一复合奖励进行联合对齐，以提高训练稳定性。

## 3. 实验设计

### 3.1 评测基准

  - *FinixHuge*（超大页面，约200页）：超长保险条款、密集大表；
  - *FinixInner*（内部工作流，约4,000页）：身份证件、体检报告、理赔病历、费用明细、费用票据。

### 3.2 对比方法
- **专用文档模型**：PaddleOCR-VL-1.5、MinerU 2.5、GLM-OCR、Dots.OCR、DeepSeek-OCR-2、FireRed-OCR、Youtu-Parsing；
- **通用大VLM**：Qwen3-VL-4B（基座）、Qwen3-VL-235B-A22B-Instruct、Qwen3.5-397B-A17B、Kimi-K2.5。

### 3.3 主要实验结果
- **OmniDocBench**：FinixDoc-VL的S^{wo-formula}=92.65，优于基座模型（86.90），但略低于顶尖专用模型（GLM-OCR 94.70、PaddleOCR-VL-1.5 94.63）；

- **FinixPhoto**：FinixDoc-VL取得67.03（最佳），比基座提高12.75分；专用模型大幅下降至40–50区间，而大VLM仍保持较强鲁棒性；

## 6. 主要结论与发现

- 金融文档解析的进步不应仅以“基准收敛区”的分数衡量，而应以系统在**低质量、高复杂度、大规模文档上的稳定性、鲁棒性和可用性**为评判标准；
- 通用VLM在低质量场景下天然比专用文档模型更鲁棒，但需要领域适应训练才能将这种鲁棒性转化为金融场景的实际收益；
- 同形字感知对比学习能有效增强ViT对金融字形差异的判别力；多阶段RL比单阶段联合RL更稳定，能同时优化文本、结构和顺序等多维目标；
- **超大页面解析是系统级问题**，仅靠增大模型规模或上下文窗口无法解决，需要“动态路由 → 结构感知分割 → 方向感知重建”的系统方案；
- 在金融高风险场景，应遵循**“宁可遗漏，不可出错”**原则，当前模型在模糊不可恢复区的幻觉问题仍需结合不确定性估计和拒绝机制解决。

- **规模与算力信息缺失**：未报告GPU数量、训练时间、推理成本等关键工程指标，难以评估方法的实际训练成本与性价比；

- **表格指标偏差未完全消除**：FinixHuge中作者虽解释了TEDS超时导致得分偏低，但未给出排除超时影响或替代指标的结果，削弱了该子集表格比较的可信度；
- **统计数据完备性不足**：无置信区间、方差或显著性检验，多个接近的分数差距可能不具统计显著性；
- **“宁缺毋滥”原则尚未落地**：论文将不确定性感知拒绝机制列为未来工作，当前系统在“模糊不可恢复区”的行为仍依赖隐式训练信号，未提供明确保障；
- **依赖性风险**：Data Factory第二阶段依赖Kimi-K2.5（外部商业/大型模型）进行标注精炼，该模型的能力变动或不可用时直接影响数据生产效率。
