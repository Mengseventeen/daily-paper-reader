## 摘要
生产环境中的金融文档验证，如薪资审计、税务合规和贷款承销，要求在企业严格约束下具备卓越的准确性、一致性和可复现性。实践中，文档以异构布局和格式呈现，内容语义丰富且依赖上下文，并嵌入业务规则，而现有流程难以可靠处理这些内容。我们提出了LAVA（逻辑感知验证与增强），这是一个基于多模态大语言模型的模块化、骨干无关的流水线，集成了四阶段设计：文档规则检索、保布局信息抽取、辅助元数据增强和可审计的符号/算术验证。LAVA支持稳健的规则接地、细粒度错误归因以及一致、可追踪的端到端执行，这些能力对于高风险部署至关重要。在包含多样化金融文档和数十条专家精选验证规则的大规模真实世界基准测试上，LAVA在幻觉控制和边缘案例处理方面优于基线，同时保持高效的token使用，展示了其在高吞吐量、时间关键验证中的实用性。

## Abstract
Financial document validation in production, such as payroll auditing, tax compliance, and loan underwriting, demands exceptional accuracy, consistency, and reproducibility under strict enterprise constraints. In practice, documents arrive with heterogeneous layouts and formats, semantically rich and context-dependent content, and embedded business rules that current pipelines struggle to process reliably. We introduce LAVA (Logic-Aware Validation and Augmentation), a modular, backbone-agnostic pipeline built on multimodal large language models, that integrates a four-stage design: document-rule retrieval, layout-preserving information extraction, auxiliary metadata enrichment, and auditable symbolic/arithmetic verification. LAVA supports robust rule grounding, fine-grained error attribution, and consistent, traceable end-to-end execution, capabilities essential for high-stakes deployment. Evaluated on a large real-world benchmark with diverse financial documents and dozens of expert-curated validation rules, LAVA outperforms baselines in hallucination control and edge-case handling while maintaining efficient token usage, demonstrating practicality for high-volume, time-critical validation.

  - 企业通常以“通用模型 + 刚性规则模块”临时拼凑应对，但幻觉频发、推理可追溯性差、跨监管模式适配脆弱、token开销随规模急剧膨胀。

## 2. 方法论：LAVA框架

LAVA（Logic-Aware Validation and Augmentation）是一个**模块化、骨干模型无关（backbone-agnostic）**的流水线，基于多模态大语言模型构建，包含四个核心阶段：

### 2.1 问题形式化
- **输入**：文档集 $D = \{d_1,...,d_N\}$（扫描PDF/图像）+ 用户验证意图 $q$（自然语言验证目标）。
- **输出**：验证结果集合 $V = \{v_k\}$，每个 $v_k$ 包含支持文档子集 $D_k$、检索到的业务规则子集 $R_k$、二元验证标签 $y_k \in \{Pass, Fail\}$、以及可审计的解释轨迹 $e_k$。

### 2.2 四阶段架构

**阶段一：文档与验证规则检索（Document & Validation Retrieval）**
- **文档检索**：预处理（OCR纠错、旋转校正）→ 基于轻量图像分类器（TinyViT）的文档类型识别 → 模板引导的NER提取元数据（日期、覆盖周期）→ 基于时间约束和文档类型过滤。
- **验证规则检索**：通过Sentence-BERT对验证意图 $q$ 做语义编码，检索top-K相关规则；利用文档类型兼容性双向过滤，形成**闭环约束交换机制**，确保下游只处理最相关的文档-规则对。

**阶段二：知识提取（Knowledge Extraction）**
- **结构化模态转换**：将文档转为HTML-like标记格式（保留表格对齐、层次结构、字段依赖），结合四项技术：
  - 结构解析（LayoutParser、LayoutLMv3、AWS Textract）
  - OCR恢复（Tesseract OCR，重构长段落到连贯span）
  - 邻近度分组（合并碎片化token为语义单元）
  - 视觉区域保留（非文本内容以图像patch输入MLLM）
- **内容过滤**：基于DOM结构、字段标签（如Name、Address）和位置线索，剔除页眉、页脚、样板文本等噪声，降低token占用、提升注意力聚焦。

**阶段三：信息增强（Information Augmentation）**
- 通过轻量LLM将每条规则分类为**符号型**（上下文相关逻辑）或**算术型**（数值计算）。
- 并行提取元数据：语言检测、文档类型、领域术语（如withholding、CPP）检测，注入提示词头部或参考块，增强模型对规则语义的对齐。

**阶段四：验证（Validation）**
- **算术处理器（Arithmetic Processor）**：采用**工具使用范式**——LLM仅负责生成Python风格公式，由确定性外部引擎（Python解释器）执行计算；引入"检查器LLM + 失败回退循环"（最多 $n_{retries}=2$ 次），以负反馈方式重新生成错误公式，确保计算可靠性与语义对齐。
- **符号推理器（Symbolic Reasoner）**：直接由通用LLM处理语义/结构性推理，降低集成开销和推理延迟。
- **提示词构建**：采用**元提示（meta-prompting）风格**的动态模板系统（基于Jinja），零样本、逐步式呈现任务相关信息，避免脆弱的少样本示例和思维链的高推理成本。

## 3. 实验设计

### 3.1 数据集与基准

- **主数据集**：专有真实世界基准——加拿大抵押贷款申请文档，来自生产级工业流程，约 **1,000份扫描PDF/图像**，涵盖多种文档类型（工资单、银行/投资对账单、T4税务表、法律协议等）。
- **文档类型**：包含约20种文档类型（见附录表3），如Appraisal、Bank Statement、Paystub、Notice of Assessment、T4系列、Separation Agreement等。
- **验证规则**：数十条由资深业务专家精选的规则，分为5类：
  - C1：内容抽取
  - C2：条件逻辑推理
  - C3：多步逻辑推理
  - C4：无约束算术一致性检查
  - C5：受约束算术一致性检查
- **辅助验证**：抽样DocVQA文档，每条文档配5条手工规则，验证框架向公开数据的可迁移性。
- **评估方式**：采用**规则级测试**（而非意图级），每个规则只适用于其定义的文档类型；真实标签由领域专家手工标注，并由业务合作方人工审计。

### 3.2 评估指标

- **幻觉控制**：
  - **事实幻觉率（FHR）**：输出中包含不基于源文档的内容（证据幻觉：预测证据子集不属于黄金证据集；公式幻觉：预测公式 ≠ 黄金公式，通过Schwartz-Zippel多项式恒等式测试判定）。
  - **数值不忠实率（NIR）**：公式计算结果偏离黄金数值。
- **边缘情况处理（ECH）**：对预定义的复杂/异常文档-规则对（占10%-25%）的误判率。
- **Token成本**：每条规则检查的平均输入/输出token数。

### 3.3 对比方法（基线）

- **VLM + Field-Level OCR**：文档图像 + 仅字段级OCR文本（带空间信息）的VQA设置。
- **LLM + Field-Level OCR**：无图像，仅文本-空间数据的QA设置。
- **LLM + Enhanced OCR（无结构化标记）**：使用与LAVA相同的OCR清洗和恢复步骤，但无结构化标记。
- 所有基线、LAVA及其消融变体统一使用 **Claude 3.7 Sonnet** 作为验证组件（max response length=5120，thinking budget=1024 tokens）。

### 3.4 消融实验（6种配置）

1. 完整LAVA
2. LAVA w/o KE（无知识提取，纯视觉推理）
3. LAVA w/ Plain-text KE（纯文本，无结构标记）
4. LAVA w/ Markdown KE（Markdown风格结构）
5. LAVA w/o IA（无信息增强）
6. LAVA w/o AP（无算术处理器，全部由符号推理器处理）

## 6. 主要结论与发现

- **LAVA在所有指标和规则类别上均优于基线**，尤其在多步逻辑推理（C3）和受约束算术一致性检查（C5）上提升显著：幻觉和数值错误相比最佳基线降低超过10个百分点。
- **幻觉控制**：C5类规则的事实幻觉率从基线的0.15-0.30降至0.05；数值不忠实率从0.10-0.25降至0.00。
- **边缘情况处理**：C5类边缘误差率从0.86-0.92降至0.08，表明对布局歧义和罕见情况的泛化能力大幅提升。
- **Token高效性**：LAVA相比VLM和LLM基线减少输入token 25%-45%，实现结构化知识一次提取、多规则复用，降低推理成本和延迟。
- **消融分析表明**：
  - 知识提取（KE）是最关键模块——缺失时C2/C3/C5错误率升至0.65-0.67；结构化标记（HTML-like）优于Markdown和纯文本，因更好地保留了列对齐和字段依赖。
  - 信息增强（IA）主要影响逻辑推理（C3错误率从0.28升至0.45）。
  - 算术处理器（AP）对计算类任务至关重要——缺失时C4/C5错误率分别升至0.10/0.56，体现确定性执行和回退机制的价值。

## 7. 优点

- **任务定位精准**：将金融文档验证形式化为多文档推理任务，填补了现有基准（VRDU、DocVQA等）缺乏合规验证逻辑的空白。
- **模块化架构设计合理**：解耦各阶段、隔离故障点、支持独立调试和替换，兼顾准确性、可维护性和可扩展性。
- **可审计性**：符号/算术验证与外部确定性引擎结合，配合LLM checker回退循环，提供细粒度的错误归因和可复现的推理轨迹。
- **骨干模型无关**：可插拔任意MLLM，不依赖特定模型，具备灵活性。
- **提示工程创新**：动态模板化提示（Jinja）依据规则逻辑和文档布局控制元数据注入的粒度与粒度，兼顾信息性和token效率。
- **评估指标严谨**：形式化定义了幻觉的两种模式（证据幻觉 vs 公式幻觉），用多项式恒等式测试判断公式等价性；区分了幻觉、数值不忠实和边缘情况失误，比单一准确率指标更具诊断力。
- **实用导向**：明确讨论token成本和业务落地影响（高吞吐、时间敏感场景），给出了成本估算。
