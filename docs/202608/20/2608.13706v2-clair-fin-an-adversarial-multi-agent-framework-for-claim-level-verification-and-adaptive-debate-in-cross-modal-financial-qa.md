## 摘要
现有针对检索增强与多智能体流程中幻觉的防御仍不完整：尽管模态之间存在分歧，证据仍被信任；辩论验证的是整体报告而非单个声明；同时此类验证仅在起草后进行，导致智能体间的错误直到最终文本才被发现。为弥合这一不足，我们提出CLAIR-Fin，一个九智能体框架，它将每个问题分解为原子声明，并维护在类型化金融声明账本中。每个声明通过以下机制解决：非对称证据权威（基于声明类型决定证据可信度，而非将所有模态视为同等可靠）；监管链验证（在起草与对抗性审查的交接点检查接地性，而非仅在流程出口）；自适应反驳循环（将有争议的声明送入对抗性辩论，其深度随辩论发现而扩展）；以及终端蕴含审计，配合持续幻觉风险指数，区分已通过审查的声明与从未被质疑的声明。我们在BB-FinQA-X上评估CLAIR-Fin，该评估集包含500道跨模态金融题，基于孟加拉国银行年报材料构建，并按查询类型、格式和难度分层。与单遍检索增强生成基线相比，它将忠实度从0.780提升至0.889，同时在证据不足时对5.4%的问题弃权，而非强行给出无依据的回答；并且在忠实度上超过了HyDE和Graph-RAG等更强的检索策略基线（≤ 0.874）。

## Abstract
Existing defenses against hallucination in retrieval-augmented and multi-agent pipelines remain partial: evidence is trusted despite modality disagreement, debate verifies an aggregate report rather than individual claims, and such verification occurs only after drafting, leaving inter-agent errors undetected until the final text. To close this gap, we present CLAIR-Fin, a nine-agent framework that decomposes each question into atomic claims maintained in a typed Financial Claim Ledger. Each claim is resolved through Asymmetric Evidence Authority, which conditions evidence trust on claim type rather than treating all modalities as equally reliable; Chain-of-Custody Verification, which checks grounding at the hand-off between drafting and adversarial review rather than only at the pipeline's exit; an Adaptive Rebuttal Cycle, which routes contested claims through adversarial debate whose depth scales with what that debate finds; and a terminal entailment audit paired with a continuous Hallucination Risk Index that distinguishes claims that passed scrutiny from claims never contested. We evaluate CLAIR-Fin on BB-FinQA-X, a 500-question cross-modal financial evaluation set built from Bangladesh Bank Annual Report material, stratified by query type, format, and difficulty. Relative to a single-pass retrieval-augmented generation baseline, it raises faithfulness ($0.780 \rightarrow 0.889$) while abstaining on 5.4% of questions when evidence is insufficient rather than forcing an unsupported response, and it exceeds stronger retrieval-strategy baselines such as HyDE and Graph-RAG on faithfulness ($\leq 0.874$).

## 2. 方法论：核心思想、关键技术细节与流程

- **框架总览**：CLAIR-Fin 是一个**九智能体**框架，将问题分解为原子声明，声明与证据存入类型化的**金融声明账本（FCL）**，经八个阶段处理：文档摄入 → 声明分解 → 多模态证据检索 → 证据融合与权威加权升级 → 对抗验证与自适应辩论 → 监管链验证 → 权威加权终端审计 → 答案综合与选择性弃权。
- **声明分解**：每个声明 `c_i = (id, text, τ_i)`，类型 `τ_i` 包括 `FACT_NUMERIC`（精确数值）、`FACT_TREND`（趋势）、`CAUSE_ATTRIBUTION`（因果归属）、`RATIO_IDENTITY`（比率/百分比）。
- **非对称证据权威（AEA）**：按声明类型对模态分配固定权重，例如 `FACT_NUMERIC` 中表格权重 0.55、工具推导 0.30、文本 0.10、图表 0.05；`CAUSE_ATTRIBUTION` 中文本权重 0.75。证据覆盖度计算为 `A(ci)=Σ_{m∈Mi} w(τ_i,m)`，当 `A(ci)<0.75` 时声明进入辩论升级，否则快速通过。
- **自适应反驳循环（ARC）**：仅对升级声明运行对抗辩论，由正方（Affirmative Counsel）起草、反方（Adversarial Counsel）提出六类攻击（数值错误、范围不匹配、财年/时间错误、因果过度声称、引用缺口、视觉过度精确），每轮按严重度分级；只有存在 `high` 严重度攻击且轮次小于上限 `ρmax=2` 时才继续反驳，使辩论深度随潜在问题而非固定预算扩展。
- **监管链验证（CoCV）**：在“起草 → 对抗审查”的交接点，用 `ℓ=entails ∧ γ≥0.5` 判断草稿是否接地；失败时最多修复一次，否则标记为“custody broken”并直接判为 `InsufficientEvidence`。该机制在最后审计之前拦截漂移。
- **终端审计**：`Judge-Auditor` 计算 `m*(ci)=argmax_{m} [w(τ_i,m)·conf_m(ci)]`，并同时记录等权反事实，写入 Authority Docket；通过蕴含门后，声明被标为 `Supported` 或 `Strongly Supported`（当 `AEAscore≥0.5`）。
- **幻觉风险指数（HRI）**：连续值 `HRI=0.40(1-γ)+0.25(1-s)+0.20·(ρ_repair/ρ_max)+0.15·min(n_high/3,1)`，区分“经实质审查”与“从未被质疑”的声明。
- **选择性弃权**：仅当没有任何声明通过审计时才整体弃权；单条声明失败仍可输出部分答案并明确标注不支持项。

## 7. 优点

- **声明级粒度**：将问题分解为原子声明并维护账本，使验证、引用和审计完全可追溯。
- **模态感知的权威分配**：AEA 避免“图表近似值与表格精确值等同”，符合金融场景实际需求。
- **验证时机前置**：CoCV 在起草与对抗审查的交接点检查，而非仅最后一步，能更早拦截错误传播。
- **自适应辩论成本控制**：辩论深度与争议严重度挂钩，避免均匀浪费预算。
- **可审计的偏差控制**：Authority Docket 记录非对称权重与等权反事实的差异，使人工设定的先验可被事后检查。
- **合理的弃权策略**：将弃权作为一等输出，并在单条声明失败时仍提供部分答案，兼顾严谨性与可用性。
- **数据与评估设计严谨**：BB-FinQA-X 分层平衡，外部专家参与验证，人类评估采用盲评与一致性统计。

## 8. 不足与局限

- **数据集范围有限**：仅基于单一机构（孟加拉国银行）、单一语言（英语）、单一报告惯例，结论未必适用于其他央行、财年定义或语言。
- **设计参数为人工先验**：AEA 权重表、HRI 权重、升级阈值与蕴含阈值均不是学习得到，也未做正式校准，只能视为合理工作点。
- **跨模态链接粗糙**：使用行标签与文本的字面子串匹配，可能漏掉语义等价引用，或产生巧合误链。
- **LLM 判断者的固有偏差**：蕴含判断由 LLM 完成，两个检查点共享同一判断模型，无法独立发现该判断者的系统偏差。
- **预算上限限制**：辩论最多 2 轮、修复仅 1 次，更复杂的争议可能无法充分解决。
- **评估范围有限**：未测试多机制组合的消融、未测固定辩论预算的替代方案、未测延迟与成本、未测对抗性/分布外问题、未测多语言/多模型泛化。
- **HRI 校准程度弱**：仅与正确率相关，并非严格校准的概率，作为超参数固定设计，外部效度证据有限。
- **应用风险**：可能引发自动化偏差（over-trust），在未评估场景下性能与弃权行为不可控；AEA 先验若对某类声明错误，可能影响公平性（尽管可审计）。
